# Ride-Sharing Platform Demo

A mobile-first web application for autonomous and traditional ride-sharing services.

## Tech Stack

- **Frontend**: React + TypeScript + Tailwind CSS + Vite
- **State**: Zustand (auth) + React Query (data)
- **Maps**: Leaflet (via react-leaflet)
- **Backend**: Flask (to be implemented separately)

## Features

### Passenger Features
- 🗺️ **Map View**: Interactive map with pickup/dropoff selection
- 🚗 **Ride Requests**: Real-time fare estimates and booking
- 📜 **Trip History**: View past and current rides
- 💳 **Payment**: Integrated payment flow

### Driver Features
- 📊 **Earnings Dashboard**: Monthly earnings and trip breakdown
- 🎯 **Ride Offers**: Accept nearby ride requests
- 🔄 **Availability Toggle**: Go online/offline

### Operator Features
- 📈 **Reports**: Trip counts, category shares, peak hours
- 📊 **Analytics**: Visual charts and statistics

### Special Features
- 🔐 **Geofencing**: Multi-hop bridged routing with visualization
- 🌓 **Dark Mode**: Full theme support
- 📱 **Mobile-First**: Optimized for mobile browsers

## Demo Instructions

### Quick Start

1. **Login**: Use any email to demo (authentication is mocked)
2. **Map Tab**: 
   - Click "Pickup location" and "Drop-off location" to see demo locations
   - Fare estimate appears when both are set
   - Click "Request ride" to simulate booking
3. **History Tab**: View demo trip history
4. **Profile Tab**: 
   - Switch between Passenger/Driver roles
   - Access GDPR request form
   - Open Operator panel

### Testing Different Roles

**As Passenger:**
- Use Map for ride requests
- View History of past trips
- Check trip details and receipts

**As Driver:**
- Switch role in Profile
- Check Earnings tab for monthly income
- View breakdown of trips

**As Operator:**
- Open Operator panel from Profile
- Select different report types
- View analytics charts

## Backend Integration

The app expects these API endpoints (Flask + SQL):

```
GET  /api/meta/enums
GET  /api/passenger/fare-estimate
POST /api/passenger/request-ride
GET  /api/passenger/nearby-vehicles
GET  /api/passenger/trips
GET  /api/passenger/trip/:id
POST /api/passenger/pay/:id
POST /api/driver/onboarding
POST /api/driver/vehicle
POST /api/driver/availability
GET  /api/driver/offers
POST /api/driver/accept/:requestId
GET  /api/driver/earnings
POST /api/gdpr/request
GET  /api/geofence/tiles
GET  /api/geofence/bridged-path
GET  /api/operator/reports
```

### Security Note
All backend endpoints use **parameterized queries only** to prevent SQL injection. No string concatenation of user input occurs in SQL statements.

## Data Flow

All calculations happen in SQL:
- Fare estimates from SQL views
- Reports generated by SQL queries
- No client-side business logic

Frontend only displays data from backend, with loading/empty/error states.
